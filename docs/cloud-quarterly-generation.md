# Cloud Quarterly Model Generation

The M1_B2_QUALITY_VETO_N30 model is generated by GitHub Actions, not Vercel.

## Architecture

```
GitHub Actions (Python) → screens 2205+ stocks → applies Quality Veto → Top 30 → Supabase
Vercel (TypeScript)     → reads Supabase → displays model → refreshes prices
```

## Running the Quarterly Generation

1. Go to GitHub → Actions → `Generate Quarterly M1_B2 Model`
2. Click **Run workflow**
3. Choose **dry_run: true** to validate without writing to Supabase
4. When ready, run with **dry_run: false** to write the validated model

## What the Workflow Does

1. Runs `src/daily_screen.py` — generates fresh YF-QVP scoring for all stocks
2. Applies Quality Veto: excludes bottom 10% quality percentile
3. Applies caps: sector ≤ 25% (7 stocks), industry ≤ 15% (4 stocks)
4. Selects top 30 by YF-QVP score
5. Validates: exactly 30, no duplicates, equal weights ~3.33%
6. Writes to Supabase if dry_run is false
7. Uploads artifacts for audit

## Dry Run vs Write Mode

| Mode | Supabase | Artifacts | Purpose |
|------|----------|-----------|---------|
| dry_run=true | No writes | Yes | Validate pipeline output |
| dry_run=false | Writes model | Yes | Production quarterly model |

## Artifacts

Each run produces:
- `m1_b2_validation.json` — Top 30 with scores, sectors, validation status
- `m1_b2_targets.csv` — Simple CSV for import/reference
- `generation.log` — Full output log

Artifacts are retained for 90 days.

## Vercel Dashboard

The Vercel dashboard reads the latest model from Supabase. It shows:
- Model source: "GitHub Actions Python engine"
- Generated timestamp
- Holdings count (should be 30)
- "Refresh Top 30 & Prices" button (Vercel refreshes prices via yfinance)

## Required GitHub Secrets

| Secret | Purpose |
|--------|---------|
| `SUPABASE_URL` | Supabase project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Service role key for write access |

## Manual Fallback

If GitHub Actions is unavailable:
1. The Vercel "Refresh Top 30 & Prices" button uses the last approved CSV (`web/data/m1_b2_quality_veto_targets.csv`)
2. It fetches latest prices and writes to Supabase
3. This is a refresh, not a fresh screen — ticker list stays the same until a new GitHub Actions run

## Price Refresh

Vercel handles price refresh independently:
1. Fetches latest closing prices via yfinance for Top 30 + portfolio holdings
2. Upserts into `price_observations`
3. Reports success/failure per ticker
4. Dashboard, Holdings, Rebalance, Performance use refreshed prices
