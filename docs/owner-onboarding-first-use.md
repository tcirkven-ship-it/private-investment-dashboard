# Owner Onboarding and First-Use Guide

## Prerequisites

- Supabase project connected and auth configured
- First user to sign up becomes the owner (`profiles.is_owner = true`)
- All application routes protected by auth middleware

---

## Step-by-Step First Use

### 1. Sign Up / Log In

1. Navigate to `/login`
2. Sign up with email and password
3. First user is automatically assigned `is_owner = true` via the `handle_new_user()` trigger
4. Subsequent users get `is_owner = false` and will see access denied on admin pages

### 2. Verify Owner Status

After login, the dashboard shows an empty state. To verify owner status:
- Navigate to `/admin/model-import` — if you see the import page, you are the owner
- If you see "Access denied. Only the application owner can access this page.", you are not the owner

### 3. Create First Portfolio

1. Navigate to `/portfolios`
2. Click **New Portfolio**
3. Fill in:
   - **Name**: e.g. "Main Brokerage"
   - **Opening Date**: e.g. today's date
   - **Starting Cash**: initial deposit amount (e.g. 100000)
   - **Notes**: optional
4. Click **Create Portfolio**
5. You are redirected to the portfolios list

### 4. Add First Transaction — Deposit

1. Click on the portfolio to open it
2. Navigate to the **Transactions** tab
3. Click **Add Transaction**
4. Set:
   - **Type**: DEPOSIT
   - **Date**: today
   - **Gross Amount**: deposit amount
5. Submit
6. The transaction appears in the list. The dashboard now shows 1 portfolio.

### 5. Add a Security (via Transaction)

The first time you add a BUY or SELL transaction, you enter a ticker symbol.
If the security doesn't exist in the database, you need to create it first.

**Option A — Create security via transaction**:
The transaction server action automatically looks up or creates the security
when you enter a ticker during a BUY/SELL transaction.

**Option B — Import securities via admin**:
Use a CSV/data import to bulk-load securities (see `data_imports` table).

### 6. Add Price Data

Price observations are required for holdings valuation.

**Import via model**: When you import and publish a model snapshot, it references
securities which must already exist.

**Manual entry**: Price observations can be inserted via the database or an admin
interface.

### 7. Add a Buy Transaction

1. Open the portfolio → **Transactions** tab → **Add Transaction**
2. Set:
   - **Type**: BUY
   - **Ticker**: e.g. AAPL
   - **Quantity**: e.g. 10
   - **Price**: e.g. 150.00
   - **Gross Amount**: quantity × price
   - **Commission**: optional trading fee
3. Submit
4. Navigate to **Holdings** tab to see the position

### 8. Import a Model Snapshot

1. Navigate to `/admin/model-import`
2. Upload a model JSON file (generated by the Python research engine)
3. Review the preview
4. Click **Import as Draft**
5. The snapshot is saved as DRAFT status in the `model_snapshots` table

### 9. Publish the Model

1. Navigate to `/admin/model-review`
2. Select the draft snapshot
3. Click **Validate** → status becomes VALIDATED
4. Click **Approve & Publish** → status becomes PUBLISHED
5. The dashboard now shows "Model: Published"

### 10. Verify Dashboard Updates

After creating portfolios, adding transactions, and publishing a model:
- Navigate to `/dashboard`
- The dashboard shows portfolio count > 0 and model = Published
- No fake or hardcoded financial values are shown
- All data comes from real Supabase queries

## Route Protection Summary

| Route | Auth Required | Owner Only | Notes |
|-------|-------------|------------|-------|
| `/dashboard` | Yes | No | Filters by `owner_id` |
| `/portfolios` | Yes | No | Lists user's portfolios |
| `/portfolios/[id]` | Yes | No | Should scope to owner (via RLS) |
| `/portfolios/new` | Yes | No | Creates portfolio for current user |
| `/admin/model-import` | Yes | Yes | Owner-only via `is_owner` check |
| `/admin/model-review` | Yes | Yes | Owner-only via `is_owner` check |
| `/model` | Yes | No | Public model view |
| `/model/history` | Yes | No | Public model history |

## Troubleshooting

| Problem | Solution |
|---------|----------|
| "Not authenticated" on dashboard | Sign in at `/login` |
| Access denied on admin pages | Only the first user (owner) can access admin |
| Portfolio creation fails | Check Name and Opening Date are filled |
| Transaction insert fails | Verify portfolio exists and all required fields |
| Security not found | Create security first or use existing ticker |
| Model import fails | Upload valid JSON with `snapshot_id`, `effective_date`, `holdings` |
| Holdings show zero | Add price observations for the securities |
| Dashboard shows error | Check Supabase connection and env variables |

## Data Flow

```
Sign up → Owner profile created
    ↓
Create portfolio → Stored in portfolios table (RLS-scoped to owner)
    ↓
Add deposit → Stored in transactions table (append-only)
    ↓
Import model → Stored in model_snapshots + model_snapshot_holdings
    ↓
Publish model → Status transitions DRAFT → VALIDATED → APPROVED → PUBLISHED
    ↓
Add securities/price data → Price observations linked to securities
    ↓
Dashboard/Holdings/Rebalance → All derived from real Supabase data
```
